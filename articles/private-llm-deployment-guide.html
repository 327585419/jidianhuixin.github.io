企业本地大模型私有化部署全流程：从选型到验收

需求梳理：把“我们要 AI”翻译成硬指标

企业里最常见的一句话是“我们也想上大模型”，但这句话不能直接变成采购单。要落地，先把它拆成四组数字：模型、并发、延迟、数据。

模型决定显存下限。7B 参数模型 FP16 权重约 14GB，INT8 约 7GB，INT4 约 4GB；70B 模型 FP16 权重约 140GB，INT4 也要约 35GB。注意这只是权重，实际还要留 KV Cache 和框架开销，通常按权重的 1.2~1.5 倍估算总显存。

并发决定吞吐。要明确“同时在线多少人、峰值每秒几个请求、平均输入输出多少 token”。延迟则要区分首字延迟（TTFT）和每 token 生成时间（TPOT），内部知识库问答通常要求首字 1~3 秒内，客服类要更快。

数据决定合规等级。是公开资料、内部文档，还是含个人信息和商业机密？这直接决定要不要内网隔离、要不要审计留痕。

可执行结论：先写一页纸的需求表，列出模型规格、峰值并发、TTFT/TPOT 目标、数据密级。没有这页纸，后面所有选型都是猜。

算力选型：按模型规模与并发反推显存与卡数

显存估算可以用一个粗公式：总显存 ≈ 权重 + KV Cache × 并发 + 框架开销。以 7B INT4 为例，权重约 4GB，单条 4K 上下文 KV Cache 约 0.5~1GB，若并发 8，则需 4 + 8×0.8 + 2 ≈ 12.4GB，单张 V100 32G 就能跑。若换 70B INT4，权重约 35GB，单卡 32G 已不够，至少双卡或上 A100 80G。

7B INT4，低并发内测单张 V100 32G需实测确认框架版本

高并发在线服务多卡 A100/H100 级按 QPS 压测扩容

V100 是 Volta 架构，16GB/32GB HBM2，带宽 900GB/s，FP16 张量核心约 125 TFLOPS，不支持 BF16 和 FP8，主流新版 PyTorch/vLLM 对 sm_70 的支持在淡化，部署前必须实测确认版本组合。A100 支持 BF16、TF32 和 MIG，80GB 版带宽约 2039GB/s，对比时要写清是 SXM4 还是 PCIe，两者带宽与功耗不同。RTX 4090 单卡 24GB、带宽约 1008GB/s，性价比高，但无 NVLink、无 ECC，多卡并行和服务器形态受限。

行情参考：截至 2026 年，二手 V100 32G SXM2 拆机卡约 3000~6000 元，PCIe 版约 6000~9000 元，九成新整机约 1.8 万~2.3 万元；云上 V100 实例月付约 3800 元级，按小时约 0.16 美元/GPU/小时起。以上仅供参考，以当日货源和云厂商报价为准。

环境交付：系统、驱动、框架、网关、权限与日志

硬件到位只是开始，环境交付才是能不能用的分水岭。标准动作包括：

  • 操作系统与驱动：Ubuntu LTS + 对应 NVIDIA Driver + CUDA/cuDNN，版本要和推理框架匹配。
  • 推理框架：vLLM、TGI、TensorRT-LLM 等按模型和卡型选择，V100 需锁定兼容版本。
  • 网关：统一 API 入口，做鉴权、限流、路由和模型切换。
  • 权限：按部门/角色分配模型和额度，避免“谁都能调”。
  • 日志：请求日志、审计日志、错误日志分离，保留周期按合规要求设定。

验收：用可量化指标说话

验收不能只看“能回答”，要压测出数字。建议至少覆盖：

  • 首字延迟（TTFT）：内部问答目标 ≤ 2 秒，客服类 ≤ 1 秒。
  • 并发数：在目标 TPOT 下稳定支撑的并发请求数。
  • 可用性：连续 72 小时压测，服务可用性 ≥ 99.5%。
  • 吞吐：tokens/s 和 QPS，按真实输入输出长度测。
  • 稳定性：显存无泄漏，长上下文不崩。

验收报告要写清测试工具、模型版本、量化方式、卡型和驱动版本。任何“感觉挺快”都不算数。

数据安全、合规与长期运维

安全落地动作要具体：内网隔离，推理服务不直接暴露公网；审计留痕，记录谁在什么时候调了什么模型；密钥管理，API Key 定期轮换、最小权限；数据不出域，敏感数据不进第三方接口。

长期运维三件事：监控（GPU 利用率、显存、温度、延迟、错误率）、备份（模型权重、配置、日志）、升级策略（模型与驱动先在小环境验证，再灰度）。V100 这类老卡升级要格外谨慎，新框架可能不再支持 sm_70。

结论/建议：本地大模型私有化不是买张卡就完事，而是需求、算力、交付、验收、运维五步闭环。预算有限可先租后买或月付整卡，验证跑通再转采购；数据敏感就直接内网隔离加审计。配置和报价随货源与版本波动，建议按当日实际情况确认。
